# Signing Word Stars for Play — commands to run yourself

You asked for these to be shown, not run for you — a keystore password is something
only you should ever type in, since if it's lost, you may permanently lose the
ability to update your app under the same Play listing.

## What a keystore actually is

A **keystore** is an encrypted file holding a private cryptographic key. Android (and
Play) uses it to prove every update to your app really came from you — Play refuses
to accept an update signed by a different key than the original upload. Two kinds:

- **Debug keystore** — auto-generated by Android tooling, same well-known password
  for every developer (`android`/`android`), used only for local testing. Play never
  accepts a debug-signed build.
- **Release (upload) keystore** — you generate this once, it's unique to you, and
  Google's **Play App Signing** program means it only has to sign the *upload*; Google
  then re-signs with its own securely-managed key for actual distribution to users.
  This means if you ever lose your upload key, Google support can usually help you
  reset it — much safer than the old model where losing the key was unrecoverable.

## 1. (Optional) Confirm your debug keystore already exists

Android tooling creates this automatically the first time you build a debug variant.
Nothing to do here — Gradle already used it earlier for `app-debug.apk`. You can list
it if you're curious:

```powershell
keytool -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -storepass android -keypass android
```

`-list -v` = print the certificate details verbosely. `-storepass`/`-keypass` = the
well-known default debug password (safe to share; this key never signs anything Play
will accept).

## 2. Generate your release (upload) keystore — run this yourself

```powershell
cd C:\Users\leo\kids-word-game\play-store\android
keytool -genkeypair -v `
  -keystore release.keystore `
  -alias wordstars `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -storetype PKCS12
```

What each flag means:

- `-genkeypair` — generate a new public/private key pair (this is the actual signing
  identity).
- `-keystore release.keystore` — the output file. **This file must never be
  committed to git** (it already isn't — see `.gitignore`).
- `-alias wordstars` — a name for this specific key inside the keystore file (a
  keystore file can technically hold more than one key; you'll only have one).
- `-keyalg RSA -keysize 2048` — the encryption algorithm and strength Google
  recommends for app signing.
- `-validity 10000` — the certificate stays valid for 10,000 days (~27 years) —
  Google requires the upload key to be valid until at least Oct 22, 2033, so this
  comfortably covers that.
- `-storetype PKCS12` — the modern, recommended keystore file format (replaces the
  older JKS format).

It will interactively ask you for:

1. A **keystore password** (used to open the file at all) — type something strong
   and **save it in a password manager**, not a text file in this repo.
2. Your name / organization details for the certificate (any values are fine — Play
   doesn't display these to end users; e.g. name "Future AI", organization "Future
   AI", city, and country code `PK` for Pakistan).
3. A **key password** (protects this specific key inside the file) — you can just
   press Enter to reuse the keystore password, which is the common choice.

## 3. Tell Gradle about it (without ever committing the passwords)

Open (or create) `play-store\android\local.properties` — this file is already
git-ignored — and add these four lines, filling in the passwords you just chose:

```properties
RELEASE_STORE_FILE=release.keystore
RELEASE_STORE_PASSWORD=your-keystore-password
RELEASE_KEY_ALIAS=wordstars
RELEASE_KEY_PASSWORD=your-key-password
```

`app/build.gradle` already reads these four properties and wires up real release
signing automatically once they're present (see the `hasReleaseSigning` block I
added) — no other file needs to change.

## 4. Rebuild — now actually signed

```powershell
cd C:\Users\leo\kids-word-game\play-store\android
.\gradlew.bat bundleRelease
```

Output: `app\build\outputs\bundle\release\app-release.aab`

Confirm it's really signed now:

```powershell
jarsigner -verify app\build\outputs\bundle\release\app-release.aab
```

You should see `jar verified.` instead of `jar is unsigned.`

## 5. Get the SHA-256 fingerprint (needed for the TWA to open with no browser bar)

```powershell
keytool -list -v -keystore release.keystore -alias wordstars
```

Look for the line starting `SHA256:` — it looks like
`AB:CD:12:34:...` (32 colon-separated hex pairs). Copy that whole value.

Then, on PythonAnywhere (Bash console), set it as an environment variable for the
Flask app — ask me to do this step and I'll walk the PythonAnywhere console the same
way I did for the earlier deploys, since it just needs the value pasted in, not a
password.

## 6. Verify the AAB with bundletool

Google's `bundletool` checks that the bundle Play will accept is actually well-formed
(catches manifest/resource errors *before* you spend an upload+review cycle on them).

```powershell
# One-time: download bundletool (open source, from Google's GitHub releases)
cd C:\Users\leo\kids-word-game\play-store
curl -L -o bundletool.jar https://github.com/google/bundletool/releases/download/1.15.6/bundletool-all-1.15.6.jar

# Validate the bundle's structure
java -jar bundletool.jar validate --bundle=android\app\build\outputs\bundle\release\app-release.aab

# (Optional) Build the device-specific APKs bundletool would generate for Play,
# and install the right one on a phone plugged in via USB debugging, to test exactly
# what a real user would receive:
java -jar bundletool.jar build-apks `
  --bundle=android\app\build\outputs\bundle\release\app-release.aab `
  --output=wordstars.apks `
  --ks=android\release.keystore `
  --ks-key-alias=wordstars
java -jar bundletool.jar install-apks --apks=wordstars.apks
```

`validate` with no errors printed means Play's own upload check should also pass.

## Keep safe, forever

- `release.keystore` (or wherever you saved it) and its two passwords.
- Store a copy outside this repo/computer too (e.g. a password manager's file
  attachment, or encrypted cloud storage) — if this machine is lost and so is the
  keystore, you may not be able to publish updates to this exact Play listing again.
